# Правила передачи

Читать: HANDOFF.md → PRODUCT.md → PROJECT_STATE.md → DESIGN.md → DESIGN_IMPLEMENTATION.md → .impeccable/design.json.

- Рабочий снимок основан на event, изменения пока отсутствуют в GitHub fork. Не смешивать со старым родительским проектом. Проверять git status, сохранять правки владельца.
- Сохранять Go/Gin/SQLite и native ES modules; не менять стек и API без задачи.
- Поток: UI → api.js → middleware → handler → service → repository → SQL. workspace.go обращается к SQL напрямую.
- Права проверять на сервере. Регистрация active staff, несколько admin — решения владельца. Приватность заметок обязательна.
- Не менять применённые миграции и не удалять настоящую БД; новые изменения схемы отдельными миграциями с проверкой копии данных.
- Не коммитить секреты, .local, реальные базы/фото. На компьютере Павла материалы создавать только на D:.
- Frontend встроен в binary; пересобирать после правок и учитывать 24-часовой cache статики.
- Проверки по задаче: go test ./..., go vet ./..., go build; браузер/JS для frontend. smoke.py только на тестовой базе.
- Сохранять дизайн «Лабораторный журнал». Действующие классы в notebook.css; .ds-* в design.json — reference-примеры.
- Обновлять PROJECT_STATE.md и HANDOFF.md после существенных изменений. При доступном Graphify после изменения кода выполнить graphify update .
- Передача не разрешает автоматически реализовывать roadmap, публиковать проект или менять реальные данные.
